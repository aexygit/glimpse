# Glimpse v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Windows desktop app that captures Aion 2 inspect packets, shows the inspected character's gear, grades it and lists the top 3 upgrades.

**Architecture:** Wails v3 app. Go packages under `internal/` with one-way dependencies (`app` -> `capture`, `protocol`, `gamedata`, `grading` -> `gear`). Pure packages (`gear`, `grading`, `protocol`) are fully unit tested; I/O packages are tested with `httptest` and offline pcap files. Svelte + TS frontend talks to Go through Wails bindings and events.

**Tech Stack:** Go 1.27, Wails v3.0.0, github.com/gopacket/gopacket v1.7.4 (`pcap`, `layers`, `reassembly`, `pcapgo`), Svelte + TypeScript + Vite, log/slog.

**Spec:** `docs/superpowers/specs/2026-10-30-glimpse-design.md`

- No cgo on Windows; `wpcap.dll` loaded at runtime by gopacket.
- Cache dir: `os.UserCacheDir()/glimpse`. Config dir: `os.UserConfigDir()/glimpse`.
- License MIT (LICENSE already in the repo, do not recreate). Do not copy code from GPL tools; read them for protocol knowledge only, credit them in README.
- No new dependency beyond the stack above without a one-line justification in the commit message.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Spec amendment

BIS entries in grading JSON carry their own `tier` and `stats` (in addition to `itemId` and `enchant`), so grading never depends on `gamedata` and works offline from the first launch. Already applied to the spec.

## Review Focus

1. A game message split across TCP segments, or several messages in one segment: the inspect must still decode exactly once. Test in Task 5 and Task 6.
2. Inspect of a character whose class has no grading file: gear still displays, grade shows `?`, no crash. Test in Task 3.
3. All items unknown and offline: gear shows `Unknown item #ID`, grading uses captured stats. Test in Task 7.
4. Game closed or restarted while the app runs: status goes back to waiting, then capturing again with no user action. Test in Task 6.
5. A BIS table with a missing slot or all weights zero: no division by zero, that slot is ignored. Test in Task 3.

### Task 3: Grading engine

**Files:**
- Create: `internal/grading/grade.go`, `internal/grading/grade_test.go`

**Interfaces:**
- Consumes: `gear.Character`, `grading.Rules` (Task 2)
- Produces:
  ```go
  type SlotGrade struct { Slot gear.Slot; Score float64; Letter string }
  type Upgrade struct { Slot gear.Slot; Gain float64; Reason Reason }
  type Reason string // "missing", "enchant", "tier", "rolls"
  type Report struct { Overall float64; Letter string; Slots []SlotGrade; Upgrades []Upgrade }
  func Grade(c gear.Character, rules map[gear.Class]Rules) (Report, bool) // false when class has no rules
  func Weighted(s gear.Stats, w map[gear.Stat]float64) float64
  ```
  Formulas exactly as in the spec "Grading" section. `Slots` sorted by slot name, `Upgrades` sorted by `Gain` desc, max 3, only `Gain > 0`.
  Reason priority: `missing` (no item), else `tier` (item tier < BIS tier), else `enchant` (enchant < BIS enchant), else `rolls`.
  Letter: highest threshold `<= score`, else `D`. Item weighted value includes sockets.

### Task 6: Capture

**Files:**
- Create: `internal/capture/capture.go`, `internal/capture/conns_windows.go`, `internal/capture/conns_other.go`, `internal/capture/capture_test.go`, `internal/capture/testdata/inspect.pcap`

**Interfaces:**
- Consumes: `protocol.Framer`, `protocol.Decode` (Task 5)
- Produces:
  ```go
  type Status string // "npcap_missing", "waiting_game", "capturing"
  type Conn struct { LocalPort, RemotePort uint16; RemoteIP netip.Addr }
  // gameConns returns TCP connections of the process named exe. Windows: GetExtendedTcpTable via golang.org/x/sys/windows. Other OS: returns nil.
  func gameConns(exe string) ([]Conn, error)
  func bpfFilter(conns []Conn) string // "tcp and (port 1 or port 2)"
  type Capturer struct { Exe string; OnStatus func(Status); OnMessage func(any) }
  func (c *Capturer) Run(ctx context.Context) error
  func replay(r io.Reader, conns []Conn, onMessage func(any)) error // pcapgo reader, same pipeline as live
  ```
  Run loop: every 2 s, if no handle, look up conns; none -> `waiting_game`; found -> open pcap on all devices matching the route to `RemoteIP`, set filter, `capturing`. Use `reassembly` with one `Framer` per server->client stream. When conns change or the process exits, close handle and loop (Review Focus 4). `recover` per packet batch, log and continue. Game exe name: confirm during Task 5 research (expected `Aion2.exe`).
  `golang.org/x/sys` is the one allowed extra dependency (Windows syscalls).
