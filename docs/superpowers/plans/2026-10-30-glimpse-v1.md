# Glimpse v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Windows desktop app that captures Aion 2 inspect packets, shows the inspected character's gear, grades it and lists the top 3 upgrades.

**Architecture:** Wails v3 app. Go packages under `internal/` with one-way dependencies (`app` -> `capture`, `protocol`, `gamedata`, `grading` -> `gear`). Pure packages (`gear`, `grading`, `protocol`) are fully unit tested; I/O packages are tested with `httptest` and recorded pcap files. Capture and framing come from `github.com/nuriland/a2kit`. Svelte + TS frontend talks to Go through Wails bindings and events.

**Tech Stack:** Go 1.27, Wails v3.0.0, github.com/nuriland/a2kit (capture: pktmon on Windows, libpcap on Linux; wire framing), github.com/nuriland/aion2-api (item data), Svelte + TypeScript + Vite, log/slog.

**Spec:** `docs/superpowers/specs/2026-10-30-glimpse-design.md`

## Global Constraints

- Code, comments, identifiers, UI copy and commit messages in English.
- No em dashes anywhere (code, docs, UI, commits). Check: `grep -rnP '\x{2014}' --exclude-dir=node_modules --exclude-dir=.git .` returns nothing before each commit.
- Comments only where not obvious, and short.
- Everything except fetching item data from the NC API works offline.
- A bad packet never crashes the app.
- Windows capture uses pktmon through a2kit: no Npcap, the app runs as Administrator (exe manifest `requireAdministrator`).
- Cache dir: `os.UserCacheDir()/glimpse`. Config dir: `os.UserConfigDir()/glimpse`.
- License MIT (LICENSE already in the repo, do not recreate). Do not copy code from GPL tools; read them for protocol knowledge only, credit them in README.
- No new dependency beyond the stack above without a one-line justification in the commit message.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Spec amendment

BIS entries in grading JSON carry their own `tier` and `stats` (in addition to `itemId` and `enchant`), so grading never depends on `gamedata` and works offline from the first launch. Already applied to the spec.

## Review Focus

1. A game message split across TCP segments, or several messages in one segment: the inspect must still decode exactly once. a2kit's wire decoder owns this; Task 6 replays a recording through the full pipeline and asserts exactly one result.
2. Inspect of a character whose class has no grading file: gear still displays, grade shows `?`, no crash. Test in Task 3.
3. All items unknown and offline: gear shows `Unknown item #ID`, grading uses captured stats. Test in Task 7.
4. Game closed or restarted while the app runs: status goes back to waiting, then capturing again with no user action. Test in Task 6.
5. A BIS table with a missing slot or all weights zero: no division by zero, that slot is ignored. Test in Task 3.

### Task 3: Grading engine

**Files:**
- Create: `internal/grading/grade.go`, `internal/grading/grade_test.go`

**Interfaces:**
- Consumes: `gear.Character`, `grading.Rules` (Task 2)
- Produces:
  ```go
  type SlotGrade struct { Slot gear.Slot; Score float64; Letter string }
  type Upgrade struct { Slot gear.Slot; Gain float64; Reason Reason }
  type Reason string // "missing", "enchant", "tier", "rolls"
  type Report struct { Overall float64; Letter string; Slots []SlotGrade; Upgrades []Upgrade }
  func Grade(c gear.Character, rules map[gear.Class]Rules) (Report, bool) // false when class has no rules
  func Weighted(s gear.Stats, w map[gear.Stat]float64) float64
  ```
  Formulas exactly as in the spec "Grading" section. `Slots` sorted by slot name, `Upgrades` sorted by `Gain` desc, max 3, only `Gain > 0`.
  Reason priority: `missing` (no item), else `tier` (item tier < BIS tier), else `enchant` (enchant < BIS enchant), else `rolls`.
  Letter: highest threshold `<= score`, else `D`. Item weighted value includes sockets.

  - full BIS character -> Overall 1, Letter `S`, no upgrades.
  - empty character -> Overall 0, Letter `D`, upgrades `[weapon missing, ring1 missing]`.

  - weapon with socket `{attack:50}` and base `{attack:60}` -> weapon score capped at 1.
  - weapon tier 4 -> reason `tier`; weapon tier 5 enchant 12 -> reason `enchant`.
  - `TestGradeUnknownClass` -> `ok == false`.
  - `TestGradeZeroWeights` (Review Focus 5): all weights 0, and a rules set whose BIS lacks `ring1` while the character has a ring1 -> no NaN, ring1 absent from `Slots`.

### Task 6: Capture

**Files:**
- Create: `internal/protocol/protocol.go` (types + nil Decode, see Task 5), `internal/capture/capture.go`, `internal/capture/capture_test.go`, `internal/capture/testdata/` (a small pcap)
- Modify: `build/windows/wails.exe.manifest` (`requireAdministrator`), `.github/workflows/ci.yml` (`libpcap-dev` on the Linux job), `README.md` (no Npcap; runs as Administrator)

**Interfaces:**
- Consumes: `a2kit.Capture(ctx, adapter, cfg)`, `a2kit.Open(path, cfg)`, `(*a2kit.Reader).Messages()`, `protocol.Decode`.
- Produces:
  ```go
  type Status string // "needs_admin", "waiting_game", "capturing", "error"
  type Capturer struct { OnStatus func(Status); OnMessage func(any) }
  func (c *Capturer) Run(ctx context.Context) error // live, all adapters ("" adapter)
  func Replay(ctx context.Context, path string, onMessage func(any)) error // same pipeline, from a pcap
  ```
  Pipeline: for each `Message`, skip client frames, call `protocol.Decode(m.Frame)`, recover a panic per frame (log, continue), send non-nil results to `OnMessage`.
  Status: `OpenLive` failing for lack of rights -> `needs_admin`, retry every 10 s. Open succeeded but no game frame for 30 s -> `waiting_game`; any game frame -> `capturing`. If the capture ends with an error, report `error`, wait 5 s and reopen (Review Focus 4). Opening is a package var so tests can fake it.
